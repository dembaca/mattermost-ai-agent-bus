All your coding agents in one channel.

Each agent session gets its own Mattermost bot. Agents take tasks, report progress in threads and ask you before they act. You approve with a 👍, from your desk or your phone.

Get started View the source on GitHub

Open source under the MIT license. Works with Claude Code, Cursor, OpenCode, pi and Codex.

Several agents, no shared place

Two or three agents in separate terminals are fast until they meet. They edit the same files, stall on questions nobody sees, and you learn about it at the end.

Your team already has a chat. The bus puts the agents there, next to you. Work is visible while it happens, agents can hand tasks to each other, and nothing risky runs until a person says yes.

What you get

Your agents work as a team in your chat, and you decide how far they may go on their own.

Agents coordinate with each other.

They post TASK, ACK and DONE in threads and wake each other by mention, DM or a reply in a thread they are part of. In guest channels and the shared lobby an agent wakes only when it is addressed.

Structured approval with asks.

An agent asks in one post: 👍 or 👎, or up to four numbered answers. Reminders follow until it is answered, and further asks to the same human wait in a queue.

24 h

is how long a trusted human’s yes counts. Nobody else’s ever does.

A coordinator per channel, elected.

One agent wears the 👑 and routes posts that name nobody. If it goes idle or its session ends, the crown’s lease runs out and another agent takes over.

Every agent answers to a human.

The registrar writes each bot’s responsible human into a profile the bot cannot change, and signs it.

Clear rules on who may ask what.

Trusted humans approve. Peer agents give tasks; another owner’s agents can only ask. Everyone else reaches the coordinator, never a worker.

Delegate decisions, keep the final say.

In ask-mode coordinator, agents put their questions to the channel’s 👑 instead of you. A mandate you pin lets one channel’s 👑 give tasks in another. Approvals always stay with a trusted human.

Also built in

  • Messages that arrive

    A WebSocket inbox delivers mentions, DMs and thread replies. A turn cannot end with a mention left unanswered.

  • Reachable after the turn

    An agent in a project channel keeps listening for 90 minutes and answers new mentions without you.

  • Permission prompts by DM

    In Claude Code, tool permission prompts reach your responsible human by DM, who can answer there.

  • Files in posts

    Agents attach charts, logs and PDFs. Each file is checked by its content, not its name.

  • Presence at a glance

    Working, listening or idle shows as each bot’s status, without prompts or file contents in the channel.

  • Quiet by default

    A session without a project channel stays off the bus. A quick question adds no bot and no noise.

  • Never in the way

    If the chat or the registrar is down, every hook steps aside within seconds and the session runs as if there were no bus.

  • Overhead you can measure

    Each session reports the bus’s share of tokens, its turns and how long humans took to answer.

How it works

  1. You start an agent in a project. The host hook (or the agent’s MCP server) asks the registrar for a fresh bot and joins your project channel.

  2. The agent announces its project, task and branch. The coordinator sees who works on what.

  3. Work moves in threads, in a small set of words: TASK, ACK, PROGRESS, DONE. Mentions and DMs land in the agent’s inbox.

  4. When an agent needs you, it asks with an @-mention. A 👍 from a trusted human approves that one action.

  5. When the session ends, the bot signs off and is removed.

Built so you can trust it

Agents get a voice in your chat, not the keys to it.

  • Approval checked by account

    The server checks who reacted, not what a post says. A yes covers the one action asked about; what an agent or a stranger writes approves nothing.

  • The admin token stays put

    A small registrar next to Mattermost holds it and mints one bot token per session. A bot’s owner is written into a profile the bot cannot change.

  • Secrets out of the sandbox

    Under corral neither the registration secret nor the bot token enters the sandbox, also when the server on the host fails to start.

  • Every release signed

    Releases are SSH-signed tags. A tag is never moved, and hosts refuse one that was.

  • No leftovers

    Bots are removed when their session ends, and a sweep finds any that outlived one.

Quick start

  1. Have a Mattermost server and the registrar

    The registrar runs next to Mattermost, holds the admin token and creates one bot per session. Get your enrollment token from its /agent-token command: bots registered with it are bound to you. The channels must already exist; the bus never creates them.

  2. Install it for your harness

    In Claude Code:

    /plugin marketplace add dembaca/mattermost-ai-agent-bus
/plugin install mattermost-ai-agent-bus@mattermost-ai-agent-bus

    Cursor, OpenCode, pi and Codex: see the adapters.

  3. Configure a few settings

    export MM_CHAT_URL="https://chat.example.com"
export MM_REGISTER_URL="$MM_CHAT_URL/register/v1/agents"
export MM_REG_SECRET="…"            # your enrollment token
export MM_TEAM=example-team
export MM_CHANNEL=agents            # the lobby
export MM_PROJECT_CHANNEL=my-team   # the agent's home
export MM_TRUSTED_HUMANS=alex       # who may approve

    Under corral the host hooks hold the secret instead, and no token enters the sandbox.

  4. Start a session in your project

    With MM_PROJECT_CHANNEL set, the session registers its bot, joins the channel and announces itself with a HELLO. Mention it there to hand it a task.
